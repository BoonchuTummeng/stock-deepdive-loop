# Vault — เข้าคลัง (L8)

ผู้เรียกจะส่งมาให้: ticker · path ของรายงาน · FACTS.md · ผลตรวจ checker (🟢🟡🔴 ต่อตัวเลข) · path ของ `references/atom-template.md` และ `rules.md` · ผู้ใช้อนุมัติแล้วว่าให้เข้าคลัง

## ก่อนเขียนทุกอย่าง
อ่าน `knowledge-base/atoms/` ที่ขึ้นต้น `<TICKER>-` และ `entities/<TICKER>.md` ที่มีอยู่ — **รันซ้ำต้องไม่ทับ ไม่สร้างซ้ำ**

## 1) Atoms — No-Verify-No-Atom
- เลือกเฉพาะข้อสังเกตที่: ผล checker เป็น 🟢 · ใช้ได้ 2 ปีขึ้นไป · มี Implication · มีไฟล์+ตำแหน่งต้นทาง
- 🟡🔴 ห้ามเป็น atom → ส่งไปข้อ 3 เป็นคำถามค้าง
- ซ้ำกับ atom เดิม (ใจความ+ตัวเลขเดียวกัน) → ข้าม รายงานว่าซ้ำกับอะไร
- ตามแบบใน `references/atom-template.md` · เลขลำดับถัดจากที่มีอยู่ · เขียน `.tmp` แล้วเปลี่ยนชื่อ
- เป้า 3–8 atom ต่อหุ้นต่อรอบ (คุณภาพกว่าจำนวน) — เกิน 8 ต้องมีเหตุผลรายข้อ
- 🔴 **Quote ต้องผ่าน Grep ก่อนเขียนทุก atom (ตรวจจริงจากไฟล์ ไม่ใช่จากความจำหรือจากผล checker):** เลือกข้อความ**ช่วงต่อเนื่องช่วงเดียว**จากไฟล์ที่อ้าง ยกตรงตัวอักษร แล้ว Grep หาประโยค/ส่วนสำคัญในไฟล์นั้นยืนยันว่ามีจริง และ `source_file` ต้องเป็นไฟล์ที่ Quote อยู่จริง (ไม่ใช่ไฟล์ที่มีแค่ตัวเลขประกอบ)
  - **ห้ามประกอบ Quote จากหลายบรรทัดหรือย่อแถวตาราง** — ถ้าหลักฐานเป็นตาราง ให้ยกแถวเดียวตามที่เอกสารเขียน หรือไม่ใส่ Quote แล้วเขียน "ตาราง: <ชื่อตาราง> แถว <ชื่อแถว> (ไฟล์:บรรทัด)" แทน
  - Quote ไม่ผ่าน Grep → แก้ให้ตรงหรือ**ไม่สร้าง atom นั้น** (ย้ายเป็นคำถามค้าง) อย่าเขียนแล้วค่อยรายงานว่าไม่ได้ตรวจ
  - เลขบรรทัดที่อ้าง (`ไฟล์:บรรทัด`) ต้องเปิดอ่านเองก่อนอ้าง ห้ามคัดลอกต่อจากรายงานด่านโดยไม่เปิด

## 2) `entities/<TICKER>.md`
- ไม่มี → สร้างหน้าสั้น (ธุรกิจ 3 บรรทัด · ลิงก์ atom · ลิงก์รายงาน · `[[sectors/<กลุ่ม>]]`)
- มีแล้ว → **ต่อท้ายหัวข้อ "วงวิจัย <YYYY-MM-DD>"** บรรทัดสรุป + ลิงก์ ห้ามเขียนทับเนื้อเดิม
- กลุ่มอุตสาหกรรมต้องเป็นชื่อใน `01-Topic-Map.md` เท่านั้น · ชื่อที่ไม่มี → เสนอและถามผู้ใช้ ห้ามตั้งเอง · หน้า sector ยังไม่มี → สร้างหน้าสั้นแล้วเพิ่มใน Topic Map (หลังผู้ใช้ยืนยันชื่อ)

## 3) `watchlist.md`
ต่อท้ายตามรูปแบบใน `atom-template.md` (path รายงานเขียนเป็น **path สัมพัทธ์ในโปรเจกต์** เช่น `paper/<TICKER>-loop-<วันที่>.html` ห้ามเขียน path เต็มของเครื่อง): **คำถามค้าง** (จากข้อ 🟡🔴 และสิ่งที่ L3 ตอบไม่ได้) + **เงื่อนไขเปลี่ยนใจ** (จากสามฉาก) ทุกแถวมี "ดูที่ไหน" ที่มีจริง และ "ดูเมื่อไหร่" ที่เป็นวันที่/งวด
ถ้ามี `./paper/_gate/premortem-*.md` → ยก**ตารางสรุปท้ายไฟล์** (เส้นเรื่อง · เงื่อนไขเปลี่ยนใจ · ดูที่ไหน/เมื่อไร) ลงเป็นแถวเงื่อนไขเปลี่ยนใจ · ถ้ามี `contrarian-*.md` → ยก "สิ่งสังเกตที่จะแยกสองฝั่งได้" เป็นแถวติดตาม · ถ้ามี `omission-*.md` ที่ชี้ตกหล่นสำคัญแต่รายงานยังไม่ได้เติม → เป็นคำถามค้าง
