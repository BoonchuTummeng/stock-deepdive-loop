# Loop — วงวิจัยหุ้นครบวง (L0–L8)

ผลิตงานวิจัยหนึ่งหุ้นให้**ไหลกลับเข้าคลังความรู้** ไม่ใช่จบที่รายงานฉบับเดียว เป้า ~60–90 นาที/หุ้น
ต่อจาก Day 1–2 ทันที: ใช้โปรเจกต์ `MyStock\` · คลัง `ทุกบริษัท\<TICKER>\` · `/new-stock` · กติกาเชื่อมโยง · No-Verify-No-Atom ที่นักเรียนมีอยู่แล้ว **ห้ามสร้างโครงซ้อน**

> อ่านกฎกลางที่ `<ราก>/references/rules.md` ก่อนเริ่ม · `<ราก>` ดู [`ROOT.md`](../../ROOT.md)
> **เพื่อการศึกษา ไม่ใช่คำแนะนำซื้อขาย** — ห้ามราคาเป้า ห้ามช่วงเข้าซื้อ ห้ามขนาดไม้ ห้ามบอกให้ซื้อ/ขาย

## ก่อนเริ่ม (ขั้นเตรียม — ไม่นับเวลา)

**P1 ตรวจสภาพแวดล้อม** — โปรเจกต์ปัจจุบันต้องมี `CLAUDE.md` และ `knowledge-base\` ⇒ ไม่มี: เตือนว่านี่ไม่ใช่โปรเจกต์ MyStock แล้ว**ถามก่อน**ว่าจะให้สร้างโครงหรือหยุด (อย่าสร้างเอง)

**P2 หารากคลังเอกสาร** — อ่านจาก `CLAUDE.md` ของผู้ใช้ (หัวข้อ "คลังหุ้น") Windows ปกติ `C:\ทุกบริษัท` · Mac `~/ทุกบริษัท` · **ห้ามเดาหรือฝัง path ของเครื่องใด** หาไม่เจอให้ถาม

**P3 ticker และตลาด** — ไม่ชัดให้ถาม (ชื่อย่อซ้ำข้ามตลาดได้) · หุ้นสหรัฐต้องตั้ง `SEC_CONTACT` (อีเมลติดต่อสำหรับ SEC)

**P4 ตรวจ NotebookLM (`nlm`)** — ลอง `nlm notebook list` (ผ่าน = ใช้ได้) · **ไม่ผ่าน (ไม่มีคำสั่ง / login หมดอายุ / ต่อไม่ได้) ต้องแจ้งผู้ใช้ทันที ไม่ข้ามเงียบ ๆ** — **พิมพ์ข้อความข้างล่างนี้ออกมาเป็นข้อความถึงผู้ใช้จริง ๆ (ทั้งก้อน ก่อนทำขั้นอื่น) แล้วรอคำตอบ ห้ามแค่เขียนในรายงานหรือบอกว่า "แจ้งแล้ว" โดยไม่ได้พิมพ์** ด้วยข้อความนี้:
> ⚠️ เรียก NotebookLM ไม่ได้ (<สาเหตุที่เห็นจริง: ไม่พบคำสั่ง nlm / login หมดอายุ / อื่น ๆ>)
> แก้: เปิดเทอร์มินัลแล้วพิมพ์ `nlm login` เข้าด้วยบัญชี Google ที่ใช้กับ NotebookLM (ถ้า login ไม่ผ่านให้ปิด Chrome ทุกหน้าต่างก่อนแล้วลองใหม่ · ไม่มีคำสั่ง nlm = ยังไม่ได้ติดตั้งตามที่สอนใน Day 1)
> เลือก: (1) login แล้วบอกให้ลองใหม่ — คุณภาพคำถามดีกว่า (2) ทำต่อโดยไม่ใช้ NotebookLM — L3 จะเป็น "อ่านเองจากไฟล์" มีป้ายกำกับ ตื้นกว่าและช้ากว่า
รอผู้ใช้เลือก · ถ้าเลือก (2) บันทึกลง `idea-card.md` และรายงานท้ายวงว่า "L3 ไม่ผ่าน notebook"
**ระหว่างวงถ้า `nlm` ล้ม (login หมดอายุกลางทาง)** ใช้ข้อความเดียวกัน ณ จุดนั้น แล้วทำต่อด้วยโหมดอ่านเองจากข้อที่ค้าง

**P5 สคริปต์** — ทุกช่องคำสั่งมีสองบรรทัด **รันบรรทัดเดียว**: Claude Code ใช้บรรทัดบน (`${CLAUDE_PLUGIN_ROOT}` ถูกแทนเป็น path จริงในข้อความของ skill นี้ตอนโหลด — ตรวจแล้วหลังติดตั้งจาก GitHub — แต่ **ไม่มีอยู่ใน environment ของ Bash**: ถ้าพิมพ์คำสั่งใหม่เองที่ไม่ได้มากับ skill ให้ใช้ path จริงที่เห็นในบรรทัดคำสั่งเหล่านี้ ห้ามพิมพ์ตัวแปรเปล่า ๆ) · Codex ใช้บรรทัดล่าง (แทน `<ราก>` ด้วย path จริง)

**P5a ส่ง path ให้ agent ย่อย** — agent ย่อย (collector, factcheck, checker, vault, writer) **ไม่รู้จัก `<ราก>`** และไม่เห็นตัวแปรข้างบน ให้จด path จริงของโฟลเดอร์ปลั๊กอินจากบรรทัดคำสั่งใน skill นี้ แล้ว**ส่ง path เต็มของ `bin/` และ `references/` ในทุก prompt ที่เรียก agent เหล่านี้** ไม่งั้นมันจะหา `bin/...` หรือ `references/...` ไม่เจอ · ตรวจครั้งเดียวว่า `python "<ราก>/bin/extract.py" --help` ไม่ error ก่อนใช้จริง

**P6 สถานะเดิม** — รัน `loop_state.py status <TICKER>` ถ้ามีขั้นที่เสร็จแล้ว (และไฟล์ผลยังอยู่) **ข้ามขั้นนั้น**; ขั้นที่ขึ้น `stale` ให้ทำใหม่

```
python "${CLAUDE_PLUGIN_ROOT}/bin/loop_state.py" status <TICKER>    # Claude Code
python "<ราก>/bin/loop_state.py" status <TICKER>                   # Codex
```

**P7 แจ้งผู้ใช้ตอนต้น** — เวลาโดยประมาณ · มีจุดหยุดรอ 2 จุด (หลัง L1, หลัง L7) · ถ้ามี `quick` บอกว่าข้ามอะไร

ทุกขั้นเริ่ม/จบ: `loop_state.py start|done <TICKER> <ขั้น>` และ**แจ้งความคืบหน้า 1 บรรทัด** (`L3 เสร็จ · 9 นาที`) เก็บเวลาไว้ทำรายงานท้ายวง

## L0 — อ่านคลังเดิม ⏱ ~2 นาที
อ่านของเดิมของหุ้นนี้ก่อนทำอะไร: `knowledge-base/entities/<TICKER>.md` · atom ที่ขึ้นต้น `<TICKER>-` · `notebooklm-qa/<TICKER>.md` · แถวใน `watchlist.md` · `ทุกบริษัท\<TICKER>\_analysis\` (งานวิเคราะห์ของผู้ใช้เอง — ต่อยอด ไม่เขียนซ้ำ)
สรุป**สิ่งที่รู้แล้ว / คำถามที่ค้าง / เงื่อนไขที่ตั้งไว้** ไม่กี่บรรทัดส่งต่อให้ L1 · ไม่มีอะไรเลย = หุ้นใหม่ บอกตรง ๆ

## L1 — การ์ดไอเดีย + แผนแหล่งข้อมูล ⏱ ~4 นาที

## L2 — เก็บเอกสาร ⏱ ~5 นาที

จากนั้นรัน `extract.py` กับโฟลเดอร์หุ้น **ด้วยโหมดปลอดภัยเสมอ** (ห้ามรันแบบไม่มีสองตัวเลือกนี้ — ไม่งั้นมันเขียนทับ `.txt` ในคลังและวาง MANIFEST.md ลงชั้นบน):

🔴 **ห้ามเริ่มเขียนถ้าไม่มีเอกสารต้นฉบับ** — ดึงไม่ได้: บอกตรง ๆ ว่าติดตรงไหน ถามว่าจะทำต่อโดยระบุข้อจำกัดหรือหยุด **อย่าเขียนจากความจำ**

- คลื่น 2 ส่ง path ของ section คลื่น 1 ให้ writer ด้วย (กันเขียนขัดกัน)

### คลาส CSS ที่ใช้ได้ (มีแค่นี้)
- โครง: `<section id="s1"><h2>1 · ชื่อ</h2>` · `<h3>` `<h4>` `<p>` `<ul>` `<ol>`

- กล่อง: `box key` (สาระหลัก) · `box warn` · `box quote` (คำพูดผู้บริหาร) · `box good` · `box note` — ข้างในขึ้นด้วย `<h4>`
- ตาราง: `<div class="tw"><table><thead>…</thead><tbody>…</tbody></table></div>` · เซลล์ตัวเลข `class="num"` · `<span class="pos">` `<span class="neg">` `<span class="mut">`
- บันได (สามฉาก): `<div class="ladder"><div class="rung"><div class="head">…</div><div class="meta">…</div></div></div>`

| **omission** (ตกหล่น) | รายงาน + FACTS + Grep ชื่อรายการในเอกสาร | อะไรที่**ไม่ได้เขียนถึงเลย** | ทุกโหมด (ถูก) |
| **contrarian** (แย้ง) | เอกสารภายในเท่านั้น | ฝั่งตรงข้ามของข้อสรุปหลักแข็งแค่ไหน | เต็มเท่านั้น |
| **premortem** (ชันสูตร) | เอกสารภายในเท่านั้น | ถ้า 24 เดือนข้างหน้า thesis ตาย ตายอย่างไร → เงื่อนไขเปลี่ยนใจ | เต็มเท่านั้น |

- `quick` = 4 ด่านแรก · เต็ม = 6 ด่าน (ด่านที่ 5–6 ไม่มีสิทธิ์ตัดสิน ผลของมันไหลลงรายงานเป็นความเสี่ยง/เงื่อนไขเปลี่ยนใจ และลง `watchlist` ตอน L8)
- ผลลง `./paper/_gate/{critic,checker,redteam,omission,contrarian,premortem}-<รอบ>.md`
- ด่านที่ 5–6 ไม่ต้องตรวจซ้ำในรอบแก้ที่ 2 (ทำครั้งเดียว) · omission ตรวจซ้ำเฉพาะจุดที่แก้

**รอด่านครบทุกด่านที่เรียกแล้ว**รวมข้อค้านเป็นรายการเดียว ส่งแก้**รอบเดียว** (ห้ามทยอยแก้ทีละด่าน) → writer ตัวเดิมแก้เฉพาะจุด → ตรวจซ้ำเฉพาะจุดที่แก้
- **สูงสุด 2 รอบ** (`quick` = 1 รอบ) · เกินแล้วยังไม่ผ่าน → **หยุดแก้ รายงานตามจริง**ว่าข้อไหนยังไม่ผ่านและทำไม ใส่ป้ายกำกับตรงจุดนั้นในรายงาน ไม่ซ่อน
- ผ่านแบบมีเงื่อนไข → เขียนข้อควรระวัง**ตรงจุดนั้น** ไม่รวมท้ายเล่ม
- redteam · omission · contrarian · premortem ไม่มีสิทธิ์ตัดสินผ่าน/ไม่ผ่าน — ผลของมันคือหลักฐานให้ตัดสิน: ข้อที่แข็งและมีแหล่งให้ใส่ในรายงานเป็นความเสี่ยง/เงื่อนไขเปลี่ยนใจ · **รายการที่ omission ชี้ว่าตกหล่นสำคัญ** ให้ writer เติมเข้ารายงานในรอบแก้เดียวกัน (ไม่แยกรอบ)

4. ตรวจซ้ำซ้อนข้าม section — **ห้ามแก้ข้อสรุป** (ถ้าข้อสรุปมีปัญหา = กลับ L5/L6 ไม่ใช่แก้เงียบ ๆ ตรงนี้)
   **แก้หลังด่านสุดท้าย (นอกรอบแก้) ทำได้เฉพาะกรณีนี้:** ข้อเท็จจริงผิดที่ checker ชี้ไว้แล้วพร้อมค่าที่ถูก (ตัวเลข/ช่วงเวลา/ชื่อรายการ) ที่เหลือหลังรอบแก้สุดท้าย ไม่ใช่ถ้อยคำ ไม่ใช่ข้อสรุป ไม่ใช่เงื่อนไขเปลี่ยนใจ — ทุกจุดที่แก้ต้อง
   (ก) **จดเป็นรายการ** (เดิมเขียนว่าอะไร → แก้เป็นอะไร → checker ข้อไหนชี้) ใส่ในกล่อง "แก้หลังด่าน" ในรายงานและรายงานท้ายวง
   (ข) **ตรวจซ้ำเฉพาะจุดที่แก้** — เรียก `checker` อีกครั้งโดยส่งแค่รายการจุดที่แก้ (ไม่ใช่ทั้งฉบับ) แล้วรัน `check_numbers.py` ซ้ำ ถ้า checker ตรวจซ้ำไม่ได้ (โควตา/ล้ม) ให้ใส่ป้าย "แก้หลังด่าน ยังไม่ตรวจซ้ำ" ตรงจุดนั้นแทน ห้ามเงียบ
   (ค) แก้เกิน 5 จุดหรือแตะถ้อยคำ/ข้อสรุป = ไม่ใช่การแก้เล็ก ให้กลับ L5/L6 หรือแจ้งผู้ใช้ตัดสิน
5. ตรวจว่ามี "เพื่อการศึกษา ไม่ใช่คำแนะนำซื้อขาย" ท้ายหน้า และไม่มีคำว่า ควรซื้อ/ควรขาย/ราคาเป้า/ช่วงเข้าซื้อ (grep)

## รายงานท้ายวง (สั้น ไม่เกิน 1 หน้า)
1. ไฟล์ที่ได้ทั้งหมด (path) · เวลาที่ใช้ต่อขั้น
2. สรุป 🟢🟡🔴 (กี่ตัว) และตัวเลขที่มาจากแหล่งรอง/คำอ้างกี่ตัว
3. สิ่งที่ด่านตรวจตีกลับและแก้แล้ว · สิ่งที่ยังไม่ผ่าน
4. 🌟 insight เด่นหนึ่งข้อ (ไม่ชัดตั้งแต่แรก) — ไม่มีก็บอกว่าไม่มี แปลว่ายังขุดไม่ลึก
5. สิ่งที่ยังไม่รู้ (ช่องว่างข้อมูล + ไฟล์ที่ต้องโหลดเอง)

## ข้อควรจำ
- ขั้นไหนล้ม (ดึงไม่ได้ agent ค้าง nlm ตาย) → **ลดระดับต่อได้ ไม่ crash**: บอกผู้ใช้ว่าข้ามอะไรและผลกระทบ แล้วเดินต่อ
- agent ที่เขียนไฟล์ต้องอ่านกลับยืนยัน ผู้เรียก (คุณ) ตรวจว่าไฟล์มีจริงก่อนไปขั้นถัดไป (`loop_state.py done` เตือนให้ถ้าไฟล์หาย)
- ถ้าผู้ใช้ให้คำสั่งใหม่กลางทาง ("ห้ามทำ X", "ทำแบบนี้เสมอ") ทำตามทันทีและแจ้งว่าจะใช้ต่อในวงนี้
